# 写讲稿

这是这条链路上唯一需要模型的一步，也是成片好不好的全部。其余环节——解析、配音、
镜头、时间轴、渲染——都是确定性的代码，写得再差它们也照跑。

> 这一份是**提炼版**，够写完一份材料。写长片、拿不准的时候读全文（35KB，
> 引擎包自带）：
> ```bash
> python3 -c "import doc2video,pathlib;print(pathlib.Path(doc2video.__file__).parent/'prompts'/'narration.md')"
> ```

---

## 三条准则，冲突时按这个顺序

1. **讲全**——该讲到的处数一处不少，不用一句概括代替一串具体内容；
2. **有出处**——每一句都能在页面上指出它是从哪儿来的；
3. **能念**——写出来的是话，不是文章。

最要避免的是**把页面压成摘要**：页面列了六个方向，就把六个方向说出来，不要说成
「围绕六大方向展开」；页面给了三个数，就把三个数说出来，不要说成「几项关键指标
都有提升」。概括听起来很顺，但观众什么也没听到——而那六个方向就在他眼前的屏幕上。

## 按预算写，这不是建议

`预算.tsv` 给了每页的秒数和字数上限。字数是这么来的：播音腔实测 **4.45 字/秒**
（含句间停顿），秒数乘以它就是这一页装得下的字数。

- **超了成片就超时长**，而音频一旦生成，长度就改不动了——只能重写、重配、重渲。
- **不够就是那一页没讲到**。页面文字少的一页本来就该短，但预算 130 字的页面
  写了 49 字，说明页面上还有大半内容没被讲到。
- 英文按词计时，不按字计时。一页里 PDF/PPT/AI 这样的词多，字数看着没超、时间
  已经超了——以 `check_script.py` 报的**预计秒数**为准。

**先写 3 页就去跑一次 `check_script.py`。** 一次写完 30 页再回头压，是最贵的
顺序：实测一份 30 页的材料第一稿 26 页超预算，合计 678 秒对目标 360 秒，
整份重写。头 3 页量一次，就知道 50 字听起来是多长，后面不会整体偏一倍。

超了怎么办：**先删补充说明，再删形容词，最后才合并条目**。不要靠删掉一处内容
来省字——那一处仍在屏幕上。
不够怎么办：**回页面找还没讲到的内容**，不要为了凑字数编一句解释。
为了凑字数编出来的一句话，比短一截严重得多。

## 先通读整份文档，再写单页

`页面.md` 是一次给全的，就是为了让你先看完再动笔。先弄清楚：这份材料在讲什么、
分几块、哪几页是同一块里的、术语和名字的准确写法。然后再逐页写。

一页一页地看着写，写出来的是九段互不相干的话；先通读再写，页与页之间才接得上。

## 一页讲多少

**判断标准：观众闭着眼睛听完，脑子里应该有页面上那些具体的东西——名字、数字、
条目，而不是一个印象。**

- **先横向铺开，再纵向展开。** 一页有四个板块，先让四个板块都被提到，再拿剩下
  的字数把重要的那个讲透。**一页只写一段就停，是最常见的问题。**
- **报了数就要点名。** 说了「三块」，三块的名字就得说出来；说了「四条链」，
  四条链就要念出来。报了数不点名，听的人在等，而你翻页了。
- **没讲到的不要提。** 不要说「还有其他几项」「限于篇幅不展开」「等等」——
  观众看得见屏幕，你不说他自己看。
- **宁可少挑两处，也不要把每一处都压成一个名字。** 一串名词念完，听的人什么
  都没得到。

## 什么时候不要改写

改写有代价：每动一次，都是一次讲错的机会。这几种照原话讲：

- **页面上本来就是口语的**——「怎么买、何时买、风险在哪里」已经是说出来的话；
- **本身就短、就准的**——「服务智能生态 助力四链融合」，拆开重说必然更长更松；
- **对仗、排比、有节奏的**——写的人斟酌过，念出来正好，打散就没了；
- **名字、数字、条目名**——见下面两条。

办法很简单：**先默念一遍页面上的原话。** 念得顺就照念；念着别扭、要倒气、
要回头看一眼才懂，才需要改。一页讲稿里有几句和页面一字不差，是正常的。

## 事实不能动，只能换说法

| 页面上 | 讲稿里 |
| --- | --- |
| 基于产业链数据构建智能体 | 我们靠产业链数据来搭这个智能体 |
| 覆盖创新链、产业链、人才链、资金链 | 覆盖创新链、产业链、人才链和资金链，四条链 |
| 16+ 数据源 / 小时级更新 | 16 个以上的数据源，最快小时级更新 |
| 一、背景及技术牵头方 | 先看背景，还有技术牵头方是谁 |

**归属和时态也是事实。** 页面说「可被本项目借鉴」「团队已有的成果」，讲稿不能
说成「本项目承担了」「我们做出了」。已有的资产、别人的项目、将要做的事，三者
不能混。拿不准归属时照页面原话讲，不要替它认领。

**专有名词、机构名、条目名照页面原词讲**——不换同义词、不用简称、不削掉
「有限公司」「研究院」这类后缀。名字改了就是另一个名字，而它正在观众眼前。

## 数字照页面的写法写

页面写 `12000` 就写 `12000`，写 `78%` 就写 `78%`。**不要改写成中文数字**：

- 播音腔自己会把 `12000` 念成「一万二千」、`6.5` 念成「六点五」，念得对；
- 而 `check_script.py` 的漏讲检测是拿页面文字比对的，写成「一万两千」它就
  认不出你讲过这一处，会误报「漏讲」。实测就是这么误报的一次。

页面自己写了同比、环比、占比就照着讲；页面没写的比较关系不要自己算——除非
两个数都在页面上，而且只占一句。

## OCR 来的页面，多一道手续

`页面.md` 里的内容如果是 `ocr_pdf.py` 补出来的，写之前先扫一眼这三样：

- **机构名、人名、专有名词**——OCR 会认错字形相近的字（实测「浙江大学」识成
  「湘江大学」、「CCAI」掉成「CCA」）。按画面上的写法讲，不要照着识别结果讲；
- **数字和单位**——识错一位就是讲错，而画面上是对的；
- **截图里的正文**——`--augment` 会把产品界面里那篇示例文章、表格里每一格都捞
  进来。那是画面里的素材，不是这一页要讲的内容。这一页在讲「产业内参分成日报、
  周报、专报三类」，不是在讲日报里那条铜矿废水的新闻。

## 跨页衔接

- 相邻两页之间要有一句搭话，但**不要强行过渡**：页面之间没有的因果不要造。
- **相邻几页的开场不要是同一个模子。** 连着三页「这一页是……」听起来像模板，
  `check_script.py` 会报，但它只抓得到最像的那几种，其余靠你自己听。

## 句子要适合念

- **一句话里，两个标点之间不要超过 34 个字**——字幕单条按标点切，超了会溢出。
- 句子的长短跟着页面上那一块的长短走；一个句式不要连用三次。
- 一长串并列要给听的人抓手：「四条链」「三个方面」先报个数，再一条条念。
- **讲内容，不要讲「页面」**：不说「如图所示」「这一页展示了」「左边是」——
  观众看的是画面，不是你在描述画面。
- 口号和名词堆要先变成一句完整的话；但**宁可少讲一处，也不要把一处讲成半句**。

## 不要写进讲稿的东西

这些会被一字一字念出来，或者把切句切乱。`check_script.py` 直接判硬伤：

`**加粗**`、`#` 标题、`- ` 列表符号、`1.` 序号、emoji、`（此处……）` 这类
占位说明、括号里的旁白注释。

**讲稿就是要念出来的那一串字，不是一份文档。**

## 按页面类型

| 页面类型 | 怎么讲 |
| --- | --- |
| 封面 cover | 一到两句：谁做的、做的是什么。机构名写全；日期、联系方式不念——那是排版 |
| 目录 agenda | 按顺序念各章名称，可以用一句串起来。不展开讲每一章 |
| 内容 content | 按页面顺序讲条目，一条一句，条目之间用页面已有的关系搭话 |
| 数据 content/table | 按页面顺序把数值讲出来，带单位和量词 |
| 图表 chart | 先说这张图在看什么（图题或坐标轴名），再讲页面标注的那几个数。不要逐点朗读，不要评价趋势 |
| 架构/流程 architecture | 逐条逐步讲，保持页面的顺序和编号，用「第一步」「然后」「最后」串 |
| 对比 | 用两边各自的名字讲，不要说「左边」「右边」——那是方位 |
| 案例 | 按背景、做法、结果的顺序讲，页面写了什么数就讲什么数 |
| 总结 summary | 念页面上的总结条目，不重新组织成新论述，不加页面没有的展望 |
| 结尾/联系 | 「感谢聆听」加一句落款就够 |

## 避免典型的 AI 腔

1. **「不是 X，而是 Y」** 这类先否定再断言的对比句式；
2. **顶针**：「……做的是数据。数据，是这条链的起点。」；
3. **给页面内容贴标签**：「这是一个非常重要的能力」；
4. **举牌词**：「值得注意的是」「不难看出」「换句话说」；
5. **同义重复**：「提升效率、提高效能」。

## 写完先自己读一遍

`check_script.py` 量的是字数、重合度、条目数、字幕长度——**读了才能发现的那几类
它量不出来**：事实漂移、半句话、行话、页与页接不上。那一遍见
[script-review.md](./script-review.md)。
