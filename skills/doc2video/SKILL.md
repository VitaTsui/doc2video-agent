# 讲解视频：PDF / PPT → MP4

一份材料变成一支会讲、会指、会切镜头的视频。**这条链路上只有一件事需要模型：
写讲稿。** 解析幻灯片、时长预算、配音、镜头、时间轴、渲染合成，都是确定性的代码，
由 `scripts/` 里的脚本调引擎完成。

配音固定是**播音腔 `zh-CN-YunyangNeural`**，不给换：讲稿的字数预算是按它的
语速算出来的，换声音预算就不作数了。

只在需要时读，别一上来全加载：

  —— 三条准则、按预算写、一页讲多少、什么时候照念、数字怎么写、页面类型对照。
  **动笔之前必须读这一份。**
- **渲染前自查**：[script-review.md](./references/script-review.md)
  —— 机器量不出来的五类问题（照读、半句话、事实漂移、行话、页与页接不上）。
- **声音与时长**：[voice-and-timing.md](./references/voice-and-timing.md)
  —— 播音腔为什么是它、4.45 字/秒从哪来、停顿由标点决定、断网了会怎样。
- **沙箱与交付**：[sandbox-and-delivery.md](./references/sandbox-and-delivery.md)
  —— 目录必须在哪、依赖怎么装、耗时、派子智能体写讲稿、成片怎么交出去。

## 开工前

### 1 · 装引擎，然后体检

引擎是 `vendor/` 里的一个 wheel（400KB），依赖单列在 `requirements.txt`：

```bash
pip install <技能包>/vendor/doc2video_agent-*.whl --no-deps \
  && pip install -r <技能包>/requirements.txt \
  && python3 <技能包>/scripts/check_env.py
```

`check_env.py` 会**真合成一句话**去试播音腔，而不是只 import 一下——它在别人的
机器上（微软的 read-aloud 接口），装得上和连得通是两件事。连不通的话，
失败会发生在渲染跑到配音那一步，那时候整份文档已经解析完了。

⚠️ **依赖缺失和材料有问题是两回事，别混。** 体检不做，后面一堆怪现象会被归到
材料上去。

### 2 · 工作目录：先验可写，再定在哪

**任何可写目录都行**，唯一的硬条件是**你和脚本都写得进去**：

```bash
D=/workspace/讲解视频 && mkdir -p "$D" && test -w "$D" && echo "可写：$D"
```

只有**要派子智能体**（分片写讲稿、派人读稿）时，工作目录才必须落在
`/workspace/myspace/` 下——那是主子之间唯一共享的投影。自己一个人跑完整条链路，
放哪儿都行。

⚠️ **实测踩过**：某平台的 `/workspace/myspace/` 是 root 属主，bash 以 ubuntu
运行，`mkdir` 直接 Permission denied。**不要在这上面耗**（sudo、逐个目录试权限、
找用户专属子目录都试过，没用）——换 `/workspace/<名>` 就好。
源文件只要读得到就行，留在 myspace 不用动。

路径一律用绝对路径。详见
[sandbox-and-delivery.md](./references/sandbox-and-delivery.md)。

### 3 · 没有文字层的 PDF：先 OCR

扫描件、把幻灯片导成图再拼的 PDF、截图拼的 PDF——页面上有字，但**取不出字**。
`prepare.py` 会当场拒绝（「这份文档 N 页，一个字都没解析出来」），拒绝是对的：
引擎不看图，硬跑只会产出一份没有内容的讲稿。

```bash
pip install rapidocr-onnxruntime                       # 约 150MB，之后识别不联网
python3 scripts/ocr_pdf.py --in 扫描件.pdf --out 扫描件-ocr.pdf
python3 scripts/prepare.py --file 扫描件-ocr.pdf ...   # 之后照常
```

它把每页渲成位图识一遍字，再**按原位置**写回不可见文字层——画面一个像素都不改。
位置要原位不是讲究：镜头照着元素 bbox 决定框哪里，文字全堆在左上角的话，
视频里镜头就一直框左上角。默认只补取不出字的那几页，有文字层的页原样保留
（**原文字层永远比 OCR 准**）。

**图多的 deck 加 `--augment` 跑一次。** 有文字层不等于文字都在文字层里——
架构图、产品截图、示意图里的字是画上去的，取不出来。实测这份 30 页方案：

| | 文字层 | 图里另有 |
| --- | --- | --- |
| 第 25 页 | 257 字 | **810 字** |
| 第 26 页 | 129 字 | **1000 字** |
| 第 27 页 | 243 字 | **1936 字** |
| 全篇 30 页 | — | 共 5712 字，20 秒识完 |

不捞出来，这几页的讲稿就是照着四分之一的内容写的。`--augment` 只补文字层里
没有的行（逐行比对，剥掉项目符号再比），已经有的跳过，不会讲两遍。

代价要知道：截图里的**正文**也会被一起捞进来（产品界面里那篇示例文章、
表格里的每一格）。写讲稿时按「这一页在讲什么」判断，不要照着截图正文念——
那是画面里的素材，不是这一页的内容。

⚠️ **OCR 出来的字会被念出去。** 写讲稿前先扫一眼 `页面.md` 里的机构名、数字、
专有名词——实测这份方案里「浙江大学」被识成了「湘江大学」、「CCAI」掉成
「CCA」。讲稿照着错的讲，而画面上是对的，这种错最难被发现。

### 4 · 优先要 PDF

PDF 的页面由 PyMuPDF 自己渲染，和原稿一模一样。PPT 要靠 LibreOffice 或
Chromium 才有好效果，**沙箱里两个都没有**，会落到内置栅格化器——只按 shape
几何画，保真度低。

拿到 `.pptx` 先问一句能不能给导出的 PDF。旧版 `.ppt` 更是**必须**先转
（python-pptx 读不了二进制 ppt）。

### 5 · 字幕字体：包里自带，不用配

字幕是烧进画面的，靠 ffmpeg 的 drawtext 画，它要一个**有中文字形**的字体文件。
沙箱里常常一个都没有——精简镜像通常只带 DejaVu，DejaVu 没有中文。

所以技能包自带一份：`vendor/fonts/NotoSansSC-Regular.otf`（8.3MB，SIL OFL 1.1，
许可证在同目录）。`lib/workspace.py` 会自动把 `D2V_FONT_PATH` 指过去，
**什么都不用设**。换成别的字体就把 `.otf`/`.ttf` 丢进那个目录，或者显式
`export D2V_FONT_PATH=/绝对路径/xxx.otf`（显式的优先）。

字体真的没了的话，引擎 0.10.31 起会**跳过字幕**并记一条降级，而不是把每个汉字
烧成方块——那正是「字幕显示的都是方块」的来历：渲染成功、文件能播、
每一条字幕都是一排空心框。`check_env.py` 的「字幕字体」一节报的就是这件事。

## 关键约束

- **讲稿是你写的，不是引擎写的。** 引擎里没有模型，也不配任何模型 Key。
  `prepare.py` 把页面内容和每页预算一并给你，就是为了让你不用再问一次就能开始写。
- **必须按预算写。** 时长是按字数估的，超了成片就超时长——**而音频一旦生成，
  长度就改不动了**，只能重写、重配、重渲。
- **配音固定播音腔。** 引擎不可用时 `make_video.py` 直接拒绝开工，不会悄悄换个
  声音接着跑。真要换，显式加 `--allow-fallback-voice`。
- **改一页只重做一页。** 出片之后改 `讲稿/pNN.md`，`--pages N` 只重配那一页、
  重渲那一段，其余片段原样复用（实测 9 秒）。
- **渲染是分钟级的，默认后台跑。** 前台跑必定被工具预算打断在中途。
- **不要替页面编内容。** 页面没写的原因、影响、预测，讲出来就是错的——
  而它会配着屏幕上的原文一起播出去。

## 执行链路

```
prepare.py        解析文档，出「页面.md + 预算.tsv + 讲稿模板」   秒级，你自己跑
   ↓
你逐页写讲稿      ← 唯一需要模型的一步，也是成片好不好的全部
   ↓
check_script.py   量字数、超时、照读、漏讲、字幕长度            秒级
自己读一遍        五类只有读了才发现的问题                      见 script-review.md
   ↓
make_video.py     配音 → 镜头 → 时间轴 → 渲染 → 合成            分钟级，后台跑
job_status.py     轮询
   ↓
summary.py        降级记录、实际时长、逐场景讲稿
   ↓
make_video.py --pages N   改哪页重做哪页
   ↓
交付 成片.mp4     sandbox_get_artifact → pin_to_workspace
```

### 1 · 解析

```bash
python3 scripts/prepare.py --file /workspace/myspace/源文件/xxx.pdf \
  --brief "8 分钟的产品讲解视频，面向企业客户，第 5 到 8 页重点讲" \
  --out /workspace/myspace/讲解视频/工作目录
```

`--brief` 里的**时长**和**重点页**会被读进预算，其余的话记进工程但不影响预算。
不说时长的话，引擎按页数自己定一个。

⚠️ `--out` 给目录，不是文件名。产出：

| 文件 | 是什么 |
| --- | --- |
| `页面.md` | 逐页的标题、类型、页面上的文字与元素。**写讲稿只读这一份** |
| `预算.tsv` | 每页的口播秒数、目标字数、页面在屏秒数 |
| `讲稿/pNN.md` | 一页一个空文件，头一行注释写着这页的预算 |
| `工程.json` | 工程 id 等元数据，脚本之间靠它传递 |

### 2 · 写讲稿

**先读 [narration-writing.md](./references/narration-writing.md)，再动笔。**

顺序是：先通读 `页面.md` 整份，弄清楚这份材料在讲什么、分几块、术语和名字的
准确写法；然后逐页写进 `讲稿/pNN.md`。一页一页看着写，写出来的是互不相干的
几段话。

⚠️ **先写 3 页，跑一次 `check_script.py`，再写剩下的。**
30 页一次写完再回头压，是最贵的顺序——实测一份 30 页的材料，第一稿 26 页超预算，
合计 678 秒对目标 360 秒，只能整份重写。头 3 页跑一次就能校准手感：
知道 50 字听起来是多长、一页四个板块要怎么分配，后面 27 页就不会整体偏一倍。

写文件用 Python 或 heredoc，别用 `echo`——讲稿里的中文标点和引号会被 shell 转义
搞乱，而那是写完才发现的。

三条准则，冲突时按这个顺序：**讲全** > **有出处** > **能念**。

最常见的两个毛病：把页面压成摘要（「围绕六大方向展开」——那六个方向就在屏幕上，
观众什么也没听到），和一页只写一段就停（页面上还有三个板块没讲到）。

**讲稿就是要念出来的那一串字。** 不要写 markdown 标记、列表符号、序号、emoji、
括号旁白——它们会被一字一字念出来，`check_script.py` 直接判硬伤。

页数多到一次写不完，按**章节**切片派执行员子智能体，别按页数硬切：
接缝要落在章节之间。做法见
[sandbox-and-delivery.md](./references/sandbox-and-delivery.md)。

### 3 · 量一遍，再自己读一遍

```bash
python3 scripts/check_script.py --dir <工作目录>
```

分两类，退出码只看硬伤：

| | 是什么 | 退出码 |
| --- | --- | --- |
| **硬伤** | 缺页、超预算、混进了念不出来的东西 | 1，不改别渲染 |
| **提醒** | 照读页面、漏讲条目、开场雷同、字幕会溢出、明显写短了 | 0，你自己判断 |

提醒之所以是提醒：机器量得出重合度和条目数，量不出**这一页是不是本来就该照念**
——页面上本来就是口语的短句，照念是对的。

**时长按成片算，不按口播算**：报的是「口播 N 秒 + 每页首尾留白 M 秒 ≈ 成片 X 秒」。
预算表里每页的秒数已经是口播口径，加起来天然小于目标——照着口播数去加长，
成片就真超了。超 5% 或短 10% 都是硬伤，短的时候会直接列出空得最多的几页。

量不出来的那五类（照读、半句话、事实漂移、行话、页与页接不上）要读了才发现。
页数少自己读，页数多或者写久了对稿子脸熟了，就派一个执行员子智能体读，
按 [script-review.md](./references/script-review.md) 回报问题清单。

### 4 · 出片

```bash
python3 scripts/make_video.py --dir <工作目录>          # 默认后台，立刻返回
python3 scripts/job_status.py --dir <工作目录> --wait 60 # 轮询
```

`job_status.py` 的退出码是给脚本判断的：**0 成功、1 失败、2 还在跑**。
`--wait` 别超过工具预算——超时被打断的是轮询，渲染在自己的进程组里继续跑，
再调一次就好。

跑完看：

```bash
python3 scripts/summary.py --dir <工作目录>
```

**第一眼看「降级」那一栏**：跑完了但打了折的地方（哪一页没讲稿用了占位、配音落到
了别的引擎、字幕没烧上）都在那儿。这些都不会让运行失败，不看就不知道。

### 5 · 改一页

```bash
# 改 讲稿/p05.md，然后
python3 scripts/check_script.py --dir <工作目录>
python3 scripts/make_video.py --dir <工作目录> --pages 5
```

改了哪几页就写哪几页。把全部页码都写上等于整片重做。

### 6 · 交付

交付 `<工作目录>/成片.mp4`：`sandbox_get_artifact` 登记 → `pin_to_workspace`。
只停在沙箱磁盘上的文件，对用户是不可见的。

## 脚本一览

七个，都接 `--dir`（`prepare.py` 是 `--out`，`ocr_pdf.py` 是 `--in/--out`），都要绝对路径。

| 脚本 | 用在 | 干什么 |
| --- | --- | --- |
| `check_env.py` | 开工前 | 逐档报能力：引擎、播音腔（真试音）、ffmpeg、渲染器、幻灯片保真度、OCR |
| `ocr_pdf.py` | 开工前 | 给没有文字层的 PDF 补一层可提取的文字（按原位置，画面不变） |
| `prepare.py` | ① | 解析文档 → 页面.md + 预算.tsv + 讲稿模板；秒级 |
| `check_script.py` | ③ | 量讲稿：字数、超时、照读、漏讲、字幕长度、格式脏东西 |
| `make_video.py` | ④⑤ | 配音→镜头→时间轴→渲染；默认后台；`--pages` 改页 |
| `job_status.py` | ④ | 轮询进度，退出码 0/1/2 |
| `summary.py` | ④ | 降级记录、实际时长、逐场景讲稿 |

`lib/workspace.py` 是共用的：工作目录的文件名、以及**在 import 引擎之前**把
音色、工程库路径、「不许调模型」这三件事写死。改这三样只改这一处。

## 环境变量：都由脚本定死，不要自己设

| 变量 | 值 | 为什么 |
| --- | --- | --- |
| `D2V_STORAGE_DIR` | `<工作目录>/工程库` | 默认是 `./storage`，会跟着当前目录跑——两个脚本在不同目录下启动就会写进两个工程库 |
| `D2V_TTS_PROVIDER` | `edge` | 预算是按这个引擎的语速算的 |
| `D2V_TTS_VOICE` | `zh-CN-YunyangNeural` | 播音腔 |
| `D2V_LLM_PROVIDER` | `mock` | 讲稿由你写。环境里恰好有 `ANTHROPIC_API_KEY` 时，也不让引擎自己去写 |
| `D2V_FONT_PATH` | `vendor/fonts/` 里那份 | 字幕字体，脚本自动填。自己 export 过就用你的 |

设置必须早于 `import doc2video`——配置在进程里是缓存的，晚一步就是「设了但没生效」，
而这种失败是静默的：视频照样出，只是换了个声音、工程落在了别处。

## 依赖

```bash
python3 scripts/check_env.py
```

| 东西 | 缺了会怎样 |
| --- | --- |
| `pymupdf` | **PDF 一份都读不出**（PDF 的解析和页面渲染全靠它） |
| `python-pptx` | PPTX 读不出（旧版 `.ppt` 它本来就读不了） |
| `edge-tts` + 外网 | **没有播音腔**。沙箱里没有本地替代，最坏是静音成片 |
| `ffmpeg`（wheel 内置） | 出不了 mp4。前面所有阶段照跑照落盘 |
| `rapidocr-onnxruntime` | 只有扫描件 / 图片 PDF 要它。缺了那种 PDF 一个字都读不出，链路走不下去 |
| `jieba` / `pypinyin` | 播音腔用不到（它自己念对多音字和缩写），只有回退本地音色时才影响读音 |
| 中文字体 | **包里自带**（`vendor/fonts/`）。真没有时字幕整片跳过并记降级，不会烧方块；画面和配音不受影响 |
| Node / Remotion | 只是镜头表现力差一档，自动回退纯 ffmpeg 渲染 |
| LibreOffice | 只影响 PPT 保真度，**PDF 不受影响** |

细节与实测版本组合见 `requirements.txt` 里的注释。

## 常见问题

| 现象 | 实际原因 |
| --- | --- |
| 成片是哑的，但一切「成功」 | 播音腔连不通，落到了静音兜底。看 `summary.py` 的降级栏——静音成片和正常成片长得一模一样 |
| 声音前后不一致 | 半路断网：引擎换了本地声音把剩下的页念完，并记了降级。恢复网络后 `--pages` 重做那几页 |
| 某一页只有一句占位话 | 那一页没写讲稿。`check_script.py` 本来会拦，跳过它就会这样 |
| 成片比目标长 | 讲稿超了预算，或者每页都在余量内但加起来超了——余量是会累积的 |
| PPT 出来很难看 | 落到了内置栅格化器。要 PDF，别在沙箱里补渲染依赖 |
| 后台任务像是没动 | 看 `状态.json` 的 `updated` 和 `运行.log` 末尾。渲染阶段单页可能几十秒不出新行 |
| 「已经有一个渲染在跑」 | 上一次的进程还活着。等它，或者确认它死了再重来——两个渲染写同一个工程会互相覆盖 |
| 工作目录建不出来、Permission denied | 那个目录是 root 属主而 bash 不是 root。别折腾权限，换一个可写目录（见「开工前 · 2」） |
| 「这份文档 N 页，一个字都没解析出来」 | PDF 没有文字层（扫描件，或整页是图）。先 `ocr_pdf.py` 补一层，或者换带文字层的原文件——引擎不看图 |
| 字幕全是方块 | 用的是没有中文字形的字体。0.10.31 起不会再这样：包里自带 Noto Sans SC，真找不到字体也只是跳过字幕（见「开工前 · 5」） |
| 成片比目标短 | 讲稿整体写少了。`check_script.py` 现在按「口播 + 每页留白」估成片时长，短 10% 以上判硬伤，并列出空得最多的几页 |
| 讲稿把名字讲错了，画面上却是对的 | 这一页是 OCR 来的。OCR 会认错字形相近的字（浙→湘）。改 `讲稿/pNN.md` 按画面上的写法改，再 `--pages` 重做那一页 |
| 第一稿大面积超预算 | 一次写完再压的典型结果。先写 3 页跑一次检查校准，再写剩下的 |

## 引擎版本

`vendor/` 里的 wheel（当前 **0.10.31**）是从 doc2video-agent 仓库打出来的。
引擎发版之后要更新它：

```bash
cd <doc2video-agent 仓库> && uv build --wheel -o /tmp/d2v-dist
cp /tmp/d2v-dist/doc2video_agent-*.whl <技能包>/vendor/
rm <技能包>/vendor/<旧版本>.whl
```

引擎的完整写作提示词（35KB）随 wheel 一起装进来了，写长片时值得读全文：

```bash
python3 -c "import doc2video,pathlib;print(pathlib.Path(doc2video.__file__).parent/'prompts'/'narration.md')"
```
